# Builder images

The build engine executes only images from the bundled, versioned manifest.
The manifest is shipped as an application resource and validated at startup.
Each entry contains a logical key, a human-readable tag, a lowercase SHA-256
digest, and the certified framework IDs.

| Gatsby | `node:22` | npm or pnpm | `public/` |
| Hugo | `hugo:latest` logical key, pinned Hugo release | none | `public/` |

The logical Hugo key is retained for profile selection; Docker always receives
the manifest's immutable `tag@sha256:digest` reference. Mutable tags are
rejected by the Docker pull and run boundaries.

## Image contract

The builder image receives `/build/manifest.json`, `/workspace/src`, and
`/workspace/out`. The manifest describes the selected profile, package manager,
project root, install command, build command, and output directory. It is
generated by the engine and is not a path or command supplied by coreapp.

Builders must:

- use the declared Node 22 or pinned Hugo runtime;
- write publishable files below `/workspace/out`;
- exit non-zero for failed installs or builds;
- tolerate dynamic non-root UID/GID execution;
- avoid requiring privileged mode, the Docker socket, or host networking.

The engine adds `--init`, resource limits, a read-only container root,
capability dropping, `no-new-privileges`, a bounded tmpfs, labels, and the
selected unrestricted outbound network mode. Cancellation and timeout perform
explicit stop, kill, and remove cleanup.

## Updating the manifest

1. Build and scan a new image for one or more already-certified profiles.
2. Publish it with a reproducible release tag and record its immutable digest.
3. Update `manifest.json`, the bundled `src/build_engine/data/manifest.json`,
   the fixture, and compatibility version together.
4. Run manifest contract tests, the eight-fixture Docker harness, `make verify`,
   and package smoke tests.

Adding a framework, runtime, package manager, or builder capability is a
separate certification change. Deferred Bun, Yarn, Zola, Generic, Angular,
Remix, Next, Nuxt, and SvelteKit support must not be added by fallback logic.
